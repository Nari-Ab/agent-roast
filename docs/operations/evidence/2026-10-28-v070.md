## Findings in 0.6.0 and selected changes

1. CLI staged checks scanned added lines only. A deleted catch body could pass;
   documentation inserted inside an existing block comment/docstring could block.
   CLI --staged now shares full-blob comparison with review. Existing findings are
   counted separately; only new enabled blockers fail. Source is read from Git OIDs.
2. test.only / fit / fdescribe were not detected. New test-focus rule detects common
   JS/TS test APIs, modifiers and contiguous multiline member chains. Guides explain
   removing focus and running the full suite; native runner protections are encouraged.
3. The worktree could weaken a staged gate through an unstaged config edit. Context
   staged review uses committed HEAD policy and reports candidate policy edits.
   An initial commit uses built-in defaults; explicit --fail-on remains available.
4. README had invalid rule IDs and pointed to a nonexistent schema. Examples now
   parse successfully, with regression coverage. Source mode limits are stated honestly.
5. .mts/.cts were omitted from supported source extensions; they are now included.

## Safety and compatibility

No checkout, write-tree, index write, project script, diff helper or hook is executed.
Tests verify byte-for-byte index/worktree preservation, immutable blob reading despite
replacement objects, fsmonitor/helper isolation, partial staging, intent-to-add exclusion,
initial commits, linked worktrees, subdirectory paths, renames and old debt.
Unmerged entries, invalid/binary/symlink/oversized source and over-limit inventories
cannot yield pass. Concurrent index/HEAD changes abort the full review, with no writes
or rollback over the external writer. Cancellation and concurrent readers are covered.

Staged CLI JSON intentionally changes to ReviewResult, mode=review, source=index,
schemaVersion=1.1.0. headSha is INDEX:<digest>, not a commit; EMPTY denotes an unborn
baseline. The programmatic auditPullRequest({staged:true}) legacy contract is preserved;
use reviewStagedChanges() for the context API. Existing explicit failOn lists remain
explicit: add test-focus to block that rule. No new runtime dependencies.
The composite Action continues installing 0.6.0 until a separately authorized release.

## Remaining limits / next evidence to collect

The lexer does not parse full language semantics, resolve imports, custom aliases or
computed property calls, and does not analyze template interpolation. Focused test
names can refer to custom APIs; fit/fdescribe aliases are constrained to test paths.
Language-aware test runner/linter rules remain useful alongside this tool. Staged
comparison keeps the existing 1000-file/2MiB-blob/50MiB-source limits and per-command
30s timeout. It spawns bounded Git reads per blob; large-repository performance needs
measurement with consenting pilot teams. This work did not add a parser, automatic
code edits, server or paid features. Pilot validation from docs/product/v060-plan.md
is still needed before claiming product-market fit or preparing investor metrics.
