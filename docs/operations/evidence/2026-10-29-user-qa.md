# Agent Roast — самостоятельное пользовательское QA

29 октября 2026 года. База: опубликованная 0.8.0, commit
`30ef289919bf9fb049dd7e2323005514566c4be1`. Исправления подготовлены в локальной
ветке `codex/agent-roast-user-qa`; новый релиз не публиковался. Версия тестового
архива осталась 0.8.0, но его содержимое отличается от публичного пакета.

## Вывод

Проект уже решает конкретную задачу: помогает заметить отключённые тесты,
сужение тестового прогона, обходы типов и очевидные заглушки перед коммитом.
Реальный Git hook блокирует плохой `commit -a`, а после исправления пропускает
повторный коммит. Старый долг можно принять без разрешения новых дубликатов.
Исключения имеют причину/срок и остаются видны в отчётах.

Однако «всё нормально» было бы слишком сильным выводом: 447 старых тестов прошли,
но самостоятельные новые сценарии нашли ошибки. После исправлений инструмент
разумно использовать как дополнительный фильтр для небольших JS/TS/Python проектов,
с согласованными blocking rules и предупреждениями для неоднозначных случаев.
Зелёный отчёт не подтверждает работоспособность приложения и не заменяет его тесты.
Эта инженерная проверка также не заменяет наблюдение за реальными пользователями
и не подтверждает спрос, удержание или готовность продукта для инвестиций.

## Воспроизведённые и исправленные проблемы

| Группа | Поведение публичной 0.8.0 | Исправление в рабочем коде |
| --- | --- | --- |
| Инициализация из подпапки | `init --ci` успешно создавал config и workflow внутри `packages/app`; `check` их не использовал, GitHub не обнаруживал workflow. | Определяется реальный корень репозитория; policy/CI создаются там, CLI показывает назначение. Существующая корневая policy сохраняется. Bare repository отклоняется до записи. Вне Git допустима инициализация указанной папки. |
| Регулярные выражения JS | `/test.only('example')/` после arrow/throw/условия могло стать blocking finding. | Лексер сохраняет ограниченный контекст между строками и различает закрытие control header и вызова. Деление и реальные регистрации тестов сохраняют обнаружение. |
| Пустые обработчики | Перенос между `catch`, параметрами и `{}` давал пропуск, включая удаление единственной строки обработки в PR. | Поиск в непрерывном маскированном source; границы отсутствующих hunks не объединяются. | Заглушки и шум | Многострочный `throw new Error(...)` и статический backtick message пропускались; обычное `TODO item not found` считалось заглушкой. | Сообщение и положение реального throw проверяются по общим исходным offsets; комментарии/примеры исключаются. TODO-маркер сужен до явно похожих на placeholder форм. |

Новых runtime dependencies и правил нет. Новое поле `directory` результата
`initProject()` сообщает фактическое назначение. Старые поля `created`/`skipped`
сохранены. Добавлен повторяемый CLI harness `scripts/verify-user-workflows.mjs`.

## Что проверено

- До изменений: весь существующий набор, 447 tests, успешно.
- Добавлено 39 regression tests с положительными/отрицательными контролями. На
  старом source 21 падал и 18 проходили; исправленный source проходит все 39.
- Итоговый полный набор: **486/486**, 28 файлов. Runner Node 22.20.0; CLI/hook
  subprocesses в этом полном прогоне используют Node 18.20.8.
- TypeScript typecheck, `git diff --check`, синтаксис нового CLI harness — успешно.
- 22 CLI workflows: публичный пакет даёт ожидаемый результат в 17 случаях;
  пять воспроизводят перечисленные выше группы ошибок. Локальный исправленный
  архив установлен через npm offline с `--ignore-scripts`; все **22/22** сценария
  проходят отдельно на Node 18.20.8, 20.19.5 и 22.20.0. Содержимое установленного
  `dist` сверено с проверенной сборкой.
- Проверены actual Git commits/hooks, working tree/index separation, доверенная
  base/HEAD policy, первый коммит, baseline multiplicity, исключение/expiry,
  сохранность HEAD/index и файлов после отказа, JSON/Markdown/GitHub/SARIF,
  symlink/binary/oversized source и invalid policy с exit 2.
- 34 exploratory detector examples классифицированы отдельно: 30 находятся в
  проверяемой области и дают ожидаемый исход после исправлений; три демонстрируют
  оставшиеся ограничения; один исключён как недокументированная цепочка Jest API
  `test.each(...).only`, а не засчитан как ошибка продукта. Корректный API:
  [Jest `test.only.each`](https://jestjs.io/docs/api#testonlyeachtable-name-fn).

Эти сценарии специально подобраны, часть — уже после обнаружения дефектов. Их
проценты **не являются** precision/recall, оценкой доли найденных production bugs
или доказательством отсутствия остальных ошибок.

## Скорость и оставшиеся ограничения

Синтетический проект: 500 TS файлов по 20 простых функций, 100 изменённых файлов.
Три локальных прогона на macOS, вместе со стартом CLI и Git reads: полный `check`
около 0,22 секунды; `review` 100 изменений около 4,9 секунды. Это локальные
наблюдения, не production benchmark. Отдельные процессы Git для blob reads —
заметное ограничение review; пакетное чтение объектов имеет смысл исследовать
следующим шагом, сохраняя лимиты, отмену и привязку к immutable snapshots.

Подтверждены пропуски `test('name', {skip: true}, fn)` и `{only: true}` встроенного
Node test runner. Собственные минимальные native fixtures действительно пропускают
тест / сужают прогон (`--test-only` для only), а анализатор их не сообщает. Это
ограничение описано в README, эти формы не объявлены поддержанными.

Выражения внутри `${...}` шаблонных строк, custom aliases, computed test APIs,
смешанные Vue/Svelte/HTML regions и полная семантика языков остаются ограничениями
лексического анализа. Имеющиеся regex guards не являются полным JS parser.

Проверка выполнена локально на macOS. Новые Linux CI и Windows прогоны, live SARIF
upload и исследования с внешними пользователями не проводились. Зависимости не
менялись; новый сетевой vulnerability audit не выполнялся.

## Воспроизведение

```sh
npm run typecheck
npm test
node scripts/verify-user-workflows.mjs dist/cli.js /tmp/agent-roast-workflows.json
```

Использовать поддерживаемый development runtime Node 20.19+ / 22.12+.
Harness создаёт и удаляет свои временные Git repositories. Для npm-пакета передать
путь к его установленному `dist/cli.js`. Никакие чужие приложения, секреты,
пользовательские media и внешний каталог `Soup` не изменялись. Результаты
публикации 0.8.0 сохранены отдельно и относятся к ранее выпущенной версии.
