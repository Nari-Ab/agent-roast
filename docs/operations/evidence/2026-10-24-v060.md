# Agent Roast 0.6.0 — context review and pilot preparation

Prepared locally on 2026-10-24 from published 0.5.0 commit
`ce97491275e209dc027ce34279894ccacdefe73e`. This is an unreleased version.

## Product decision

A plausible initial segment is small teams reviewing AI-assisted changes. That segment
is a hypothesis: no customer interview or paid commitment was obtained in this work.
The new workflow focuses on a demonstrable gap: added-line checks can miss a regression
introduced by deleting handling code and can flag examples added inside existing
multi-line comments. Full before/after source comparison addresses those cases.

Existing broad code-review products already offer contextual analysis and policy
customization. Offline execution and baselines are not exclusive advantages. See
`docs/product/v060-plan.md` for primary-source comparisons and an explicit pilot plan.
No investor interest, market validation, production accuracy or customer ROI is claimed.

## Delivered

- `review --base <trusted-ref> [--head <ref>]`: resolve immutable refs, compare full
  source in changed files from merge-base to head, report new/existing/disappeared
  findings, and gate new findings only. No AI attribution tags or manual baseline
  are required. Source trees are never checked out or executed.
- Policy comes from the supplied base tip, not the candidate or worktree. Candidate
  policy-file changes are shown and ignored for the current review. The base tip and
  merge-base are separately reported, including when base advanced after branching.
- Matching preserves multiplicity and handles Git-recognized renames and line shifts.
  Disappeared patterns are not called verified fixes. Moving source to an unsupported
  extension is incomplete rather than a claimed fix.
- Async Git reads bound stdout, stderr, blob sizes, changed-file inventory and per-
  command time. Cancellation, missing history, binary/source symlinks, invalid UTF-8,
  partial clones and ambiguous ancestry cannot produce a passing complete review.
  Git replacement objects and ambient repository-redirection variables are disabled.
- `check/review --format sarif`: offline SARIF 2.1.0 with rule metadata, relative URIs,
  occurrence fingerprints and explicit incomplete status. No source snippets are
  embedded in SARIF; existing JSON/Markdown evidence still contains code snippets.
- GitHub summary and outputs expose completeness and new/existing/disappeared counts.
  Action preparation selects context review by default, preserves `mode: audit`,
  installs outside candidate npm configuration and rejects `pull_request_target`.
- Added a transparent labeled regression corpus and a pilot scorecard/validation plan.
  No new runtime dependencies, hosted service, telemetry, automatic code edits,
  user account, payment flow or investor outreach was added.

## Limits and release boundary

The existing six detectors remain heuristics; there is no AST/type analysis, semantic
proof or broad SAST coverage. Snippet matching is not semantic identity; formatting,
file-extension changes or unrecognized renames may require fresh review. Disabling a
policy in a future approved base is possible by design; base policy is trusted input,
not a defense against a malicious maintainer. Baseline/history/PR commands remain
available; no released tags were changed in this work.

Review covers changed supported files, not the whole tree. Generated/ignored/non-source
changes are counted separately. Limits are 1,000 changed files, 2 MiB/source blob,
50 MiB aggregate source and 30 s/Git command. Partial clones and multiple merge-bases
are refused. An incomplete pair contributes no claimed new/existing/fixed counts and
forces exit 2. Complete findings can still be included as partial evidence.

SARIF introduced-only review must use its own analysis category; it is not a full scan
of outstanding alerts. GitHub may not inline deletion-only findings anchored on
unchanged lines. Markdown/JSON summaries retain the complete finding location.

No GitHub push, new npm publication or live pilot was performed. The prepared Action
pins 0.6.0 and becomes usable remotely only after npm publication and release/tag updates.
The product pilot plan explicitly distinguishes test results from adoption or revenue.
