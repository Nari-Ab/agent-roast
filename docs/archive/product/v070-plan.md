# Agent Roast 0.7: надёжная проверка перед коммитом

## Основания

Аудит 0.6.0: все 212 тестов проходят, но локальный --staged читает только добавленные
строки. Удаление единственного обработчика не обнаруживается; примеры в существующем
комментарии могут давать ложную тревогу. Фокусированные тесты (.only / fit / fdescribe)
не распознаются. В README есть отвергаемый программой пример config и несуществующий
schema.json. Открытых issues в GitHub на 28 октября 2026 нет; это не доказывает
отсутствия проблем или подтверждённый спрос.

## Объём 0.7

- `--staged` и `review --staged`: полные версии изменённых файлов из HEAD и индекса,
  только новые находки блокируют; общая реализация с review. Старый программный
  auditPullRequest({staged:true}) оставлен для совместимости как added-lines API.
- Политика из HEAD; изменения config в индексе/рабочей копии не ослабляют gate.
  На первом коммите — встроенная политика, CLI --fail-on для явного переопределения.
- Чтение index diff один раз фиксирует mode/OID каждого blob. Индекс и рабочие файлы
  не записываются. В конце повторно проверить HEAD и inventory; при изменении — exit2.
- Неразрешённые конфликты, неподдерживаемые source blobs, отмена и лимиты не дают pass.
- Новое правило test-focus: JS/TS семейство, вызовы it/test/describe/suite.only,
  Playwright test.describe.only, fit/fdescribe в обычных test paths. Учитывать пробелы,
  комментарии и разбиение member chain по строкам. Не делать выводов о произвольных
  одноимённых пользовательских API или значениях строк. Не добавлять автоматический fix.
- Исправить документацию и проверить её config-примеры.

## Критерии приёмки

Удаление handler обнаруживается; комментарий не создаёт находку; старый долг не
блокирует; дополнительные дубликаты блокируют; partial staging читает именно индекс;
первый коммит, linked worktree, subdirectory, rename и unmerged корректны. Смена HEAD
или индекса до конца проверки не выдаёт успешный результат. Настройки и экспорты
поддерживают новое правило. Typecheck и весь набор тестов проходят Node18/20/22.
Публикация в этот этап не входит.

Польза релиза проверяется инженерными сценариями; спрос, retention и платёжная
готовность по-прежнему требуют реальных пилотов из v060-plan.md.
