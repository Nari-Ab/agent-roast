## Independent adversarial checks sent to the implementation owner

- Baseline1 plus exceptioncount1 for the same fingerprint could otherwise stack and
  accept two identical findings. Shared occurrence budgets must preserve the new
  duplicate. Reproduced through the current APIs; root added a regression and fix.
- Active exception changed SARIF occurrence numbering because accepted records were
  appended after actionable records. Expiry/--ignore-exceptions should not relabel
  the same source occurrence. Reported with line/key pairs for root correction.
- Config schema should mirror runtime ignorePaths limits rather than suggesting
  policies which the loader refuses. Root synchronized the limits.

## Limits and follow-up questions

The public site still uses a remote web font; that is stated separately from the
installed CLI's offline analysis. No code is submitted to the site. Static examples
are not executed analysis. The CLI's heuristic parser has language/import/alias
limits and should complement native runner/linter checks, not replace them.

Optional GitHub summary-file write failures currently can stop report emission in
context CLI mode. Badge --since global/subcommand precedence and unsupported global
options on utility commands deserve small CLI controls if those paths are retained.
These are UX/compatibility observations, not evidence of a gate bypass in new context
checks. User testing must still determine signal usefulness and adoption cost.

Final integration: optional GitHub-artifact failures now retain the actual stdout
report/status; badge global --since precedence is covered, unsupported utility
--ignore-exceptions is rejected, and SARIF occurrence identities/baseline budgets
have regression tests. Full final evidence is in 2026-10-28-v080.md.
